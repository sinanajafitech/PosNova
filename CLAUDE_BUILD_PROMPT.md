I have a working Next.js backend (`AAtish/Admin`) for a pizza restaurant's
ordering platform. It already exposes a device/EPOS API at
`https://admin.firehut.uk/api/device/*`, used today by an Android Kitchen

Key facts about the real system (all reflected in `openapi.yaml`):

- **Auth**: `POST /api/device/auth/login` (username/password issued from
  Admin → Settings → Devices) returns a bearer token good for 180 days.
  Every other call needs `Authorization: Bearer <token>`.
- **Order pop-up**: driven by a Socket.IO `new_order` event (emitted when
  something calls the server-to-server `POST /api/orders/broadcast` with
  `X-Broadcast-Secret`), backed up by 15-second polling of
  `GET /api/device/orders/pending` in case the socket connection drops.
- **Menu catalog**: `GET /api/device/menu` returns active categories with
  their enabled products (price, allergens, item type, sizes) and the
  global add-ons list — for a till building its own walk-in/phone orders.
  Orders placed on the website still arrive with items already resolved
  inline (`DeviceOrder`), independent of this endpoint. No logo/branding
  upload endpoint exists — `logoUrl`, `storeName`, `primaryColor` ride
  inside the login and pending-orders responses instead.
- **No generic feature-flag system exists.** The only toggle today is
  accepting-orders (open/closed), via `GET`/`POST /api/device/store-status`.
- Printing (`/orders/{id}/receipt`, `/orders/{id}/ticket`) hands back
  structured JSON for the Android app's own Sunmi InnerPrinter SDK
  formatting — it does not return pre-rendered print blocks.

## Endpoint quick reference

Base URL: `https://admin.firehut.uk`

| Purpose | Method & path | Auth |
|---|---|---|
| Device login → bearer token | `POST /api/device/auth/login` | none |
| Full food catalog (categories, products, sizes, add-ons) | `GET /api/device/menu` | Bearer |
| Pending orders (poll every 15s) | `GET /api/device/orders/pending` | Bearer |
| Order history (accepted onward) | `GET /api/device/orders/history?limit=` | Bearer |
| Accept an order | `POST /api/device/orders/{id}/accept` | Bearer |
| Reject an order | `POST /api/device/orders/{id}/reject` | Bearer |
| Customer receipt data (for local print) | `GET /api/device/orders/{id}/receipt` | Bearer |
| Kitchen ticket data (for local print) | `GET /api/device/orders/{id}/ticket` | Bearer |
| Read store open/closed | `GET /api/device/store-status` | Bearer |
| Set store open/closed | `POST /api/device/store-status` | Bearer |
| End-of-day Z report | `GET /api/device/z-report?date=YYYY-MM-DD` | Bearer |
| Push a new order to connected devices (server-to-server only) | `POST /api/orders/broadcast` | `X-Broadcast-Secret` header |

Socket.IO (connect to `https://admin.firehut.uk`): `new_order`,
`order_status_updated`, `order_payment_updated`, `store_status_updated`.

Customer ordering site (separate app): `https://firehut.uk`
